## 交付内容（对应用户诉求 ⑦「长截图（滚动截屏）」）

| 部分 | 说明 |
| --- | --- |
| `src/scroll/ScrollStitcher.{h,cpp}` | 拼接核心（纯计算，8 个单测）：4px 网格候选 → 全宽锚点行 + 截尾均值打分 → ±4 精修；残差拒帧；跨帧固定行（页头/底栏）与贴边滚动条列的自动检测与裁剪 |
| `src/scroll/ScrollCapturer.{h,cpp}` | 取帧循环：定时抓选区（复用 `captureRect`）→ 喂给 stitcher，带结束条件与进度信号 |
| 指示器 | **复用** `RecordingIndicator`（新增"滚动截屏"模式：文案换成「长截图 已拼 N px」、按钮换成「完成」），放在选区外 + 靠自排除 → 不会进帧 |
| 入口 | ①就地标注工具条新增「长截图」格 + **`Ctrl+L`**；②命令行 `seashot --scroll-capture [--rect x,y,w,h] [--save png] [--scroll-ms N]` |
| 交付 | 脚本式直接落盘；交互式弹结果浮层（可复制/保存/贴图/编辑）——复用既有链路 |

**怎么用**：按热键 → 选区域 → 点工具条「长截图」（或 `Ctrl+L`）→ **自己滚页面** →
滚到底/停下几帧后自动收工（也可以点指示器上的「完成」或按 `Esc` 提前结束）→ 得到长图。

设计上**不注入滚动**（不合成滚轮事件）：用户滚轮、触控板、拖滚动条、按 PageDown 都行，
不依赖具体应用，也不用去猜"滚多少才合适"。

## 还没验证的（诚实列出，别当成"已经没问题"）

1. **平滑滚动 / 分数像素位移**：探针只验了整数偏移。真实浏览器平滑滚动时，
   中间帧的偏移可能是 123.7px 这种 —— 这时残差会明显变大，实现会**拒掉这一帧**
   （实测 22 帧里拒了 6 帧，最后仍然拼对）。但"连续拒帧到上限就收工"这条路径
   只在动画场景下才会触发，目前没有专门验证。
2. **一直在动的页面**（视频/动画/自动轮播）：会走"连续拒帧"分支收工，提示
   "页面一直在动（有动画/视频？），只能拼到这里" —— 没有实测过这类页面。
3. **固定页头/底栏的自动裁剪**：单测里用合成内容验过（48/32 行都被认出并裁掉），
   真实网页（比如带 sticky 顶栏的站点）还没实测。
4. **超长页面**：上限 20000px（约 72MB 内存）；超过就停。真到那么长时的内存与耗时没量过。
5. **不响应滚轮的应用**（例如某些终端/画布）：那本来就滚不动，会按"没滚动"收工，
   拿到一张与选区等高的图。

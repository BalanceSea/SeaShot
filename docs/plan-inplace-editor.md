# 就地编辑改造计划（对齐 QQ 截图 / PixPin）

> 用户诉求（2026-10-16）：「编辑图片请参考 QQ 的图片编辑或 PixPin 的，现在的图片编辑达不到我想要的效果」
>
> 已确认的方向：
> 1. **改成就地编辑**（核心，架构级）
> 2. 工具条紧凑化（图标为主）
> 3. 图片按 **1:1** 显示，不缩放
> 4. 选完可**继续调整选区**，标注不丢
> 5. 快捷键对齐 QQ/PixPin
> 6. 补：**贴图/钉图到屏幕**
> 7. 补：**长截图（滚动截屏）**
> 8. 补：**OCR 文字识别**

---

## 1. 差距分析：为什么现在"不像"

| 维度 | QQ 截图 / PixPin | SeaShot 现状 | 性质 |
| --- | --- | --- | --- |
| 编辑位置 | 选完**直接在屏幕上标注**，不打开新窗口 | 打开独立 `EditorWindow`（深色画布、图居中） | **架构差异** |
| 工具条 | 紧凑**图标条**，贴在选区外沿，跟随选区 | 独立窗口顶部宽工具条（图标+文字） | 交互差异 |
| 显示比例 | 1:1，所见即所得 | 独立窗口里按窗口大小缩放/适应 | 交互差异 |
| 选区 | 标注期间仍可拖边改尺寸、重选 | 选区确定后交给编辑器，改不了 | 能力缺失 |
| 结果动作 | 保存/复制/贴图 与工具同排 | 顶栏保存/复制，另有导出浮层 | 布局差异 |

**结论**：主要矛盾是第一条。美化现有独立窗口解决不了"不像"的问题，必须把标注搬进**选区覆盖层**。

---

## 2. 架构方案

### 2.1 复用现有件（已具备，不必重写）

- `src/overlay/Overlay.{h,cpp}`：layer-shell 全屏覆盖层 + 框选（已有 `Intent{Screenshot,Record}`）
- `src/editor/Annotation.{h,cpp}`：标注数据模型（矩形/椭圆/箭头/画笔/高亮/文字/序号/模糊/马赛克，图像坐标）
- `src/editor/AnnotationDocument.{h,cpp}`：增删改 + 撤销/重做
- `src/editor/AnnotationRenderer.{h,cpp}`：`renderAnnotations()` 唯一导出出口；区域特效（模糊/马赛克）已与预览共用
- `src/app/Toast.{h,cpp}`：自绘卡片 + 命中测试 + layer-shell 摆放（工具条可以照这个模式做）

### 2.2 要新增的状态机

`Overlay` 增加一个"标注阶段"，与现有阶段串起来：

```
Idle → Selecting（拖框/悬停高亮窗口）
     → Annotating（**新增**：选区已定，就地标注 + 浮动工具条 + 可拖手柄改选区）
     → Done（保存/复制/贴图/进编辑器/取消）
```

标注阶段的关键点：
- 覆盖层已经是**全屏 layer-shell 表面**，把冻结的屏幕内容按 1:1 画上去，标注直接画在同一坐标系里
  → 天然满足「1:1 显示，不缩放」
- 标注坐标沿用**图像坐标**（与 `Annotation` 现有约定一致），选区变化时只改"图像原点映射"，标注不动
- 工具条：**自绘**（照 `Toast` 的做法：`QWindow::setMask` 限输入区 + 缓存位图 + 脏区重绘）。
  不建议用子控件：layer-shell 上子控件的输入区域/合成行为在多轮调试里都出过问题（见 ISSUE-001/007）

### 2.3 选区可调整

- 选区内侧 8 个手柄 + 外侧边框拖动，实时更新 `SelectionResult.logicalRect`
- 标注存的是**相对选区的图像坐标**，所以拖选区时标注跟着走、不丢
- 缩到小于标注范围时：不裁剪标注数据，只是显示被裁（导出时按新选区裁）

### 2.4 快捷键（对齐 QQ/PixPin）

| 键 | 动作 |
| --- | --- |
| `1`–`9` | 依次切换：选择/矩形/椭圆/箭头/画笔/高亮/文字/序号/马赛克 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 |
| `Ctrl+C` / `Ctrl+S` | 复制 / 保存 |
| `Ctrl+A` | 全选（整屏） |
| `Enter` | 完成并复制 |
| `Esc` | 取消当前操作（有标注时先清草稿，再退出） |
| `Delete` | 删除选中标注 |
| 方向键 | 微调选区（`Shift` 加速） |

## 3. 分阶段交付与验收

### Phase A：就地编辑骨架（核心，其余都依赖它）
- `Overlay` 增加 Annotating 阶段；选完不退出，进入标注
- 1:1 绘制冻结屏幕 + 选区边框/手柄
- 自绘紧凑**图标**工具条，贴在选区下方（下方放不下则上方）
- 复用 `AnnotationDocument`/`Annotation` 做绘制与命中；撤销/重做可用
- 保存/复制/取消 三个动作接到现有链路
- **验收**：选完 500ms 内出现工具条；标注 1:1 无缩放误差（与选区像素对齐）；`Ctrl+Z` 生效；`Enter` 落剪贴板；无独立窗口弹出

### Phase B：选区可调整 + 快捷键
- 8 手柄拖动改选区；标注跟随
- 上表全部快捷键
- **验收**：拖选区后标注相对位置不变；快捷键逐条实测

### Phase C：贴图/钉图
- 把当前结果钉成屏幕上的一块浮窗（layer-shell `LayerOverlay`），可拖动/滚轮缩放/`Esc` 关闭
- 支持多张贴图并存；右键菜单：复制/保存/关闭
- **验收**：钉图后切到全屏应用仍可见（layer-shell overlay 层）；关闭无残留

### Phase D：长截图（滚动截屏）
- 思路：固定区域 → 逐帧抓取 → **重叠区匹配拼接**（按行做相关性/相位对齐）→ 高度上限与手动结束
- 风险：动效/固定悬浮元素会拼歪；需要"暂停/回滚"兜底
- **验收**：对一个长网页连续滚动 3 屏，拼接无错位/无重影（给出实测样张）

### Phase E：OCR
- **依赖**：`tesseract` 已装，但**语言包只有 `afr`/`osd`** → 需 `tesseract-data-chi_sim`、`tesseract-data-eng`
- 流程：选区 → OCR → 结果面板（可复制全部/逐行复制）
- **验收**：对中文/英文各一张截图识别，给出实测文本与耗时

## 4. 风险与未决

1. **Phase A 是最大的一次改动**：会动到截图主链路（Phase 1 验收覆盖的路径），必须保证 `--rect`/`--save` 等脚本式调用**行为不变**，否则验收与自动化全崩。做法：标注阶段只对**交互式**截图开启，脚本式直接沿用现有链路。
2. **现有 `EditorWindow` 的去留**：Phase A 完成后它就是"可选的二次编辑"（QQ 也有从工具栏进编辑器的入口）。
   建议保留但降级为入口之一，不删（`--edit` 与 Phase 2 验收还依赖它）。
3. **工具条自绘的工作量**：图标、hover/按下态、提示气泡、工具切换都要自己画。可先只做图标+hover，提示气泡后补。
4. **长截图（Phase D）不确定性最高**：拼接算法与滚动检测都没有现成验证，可能需要在 Phase 0 式的探针里先做可行性验证。
5. **OCR 语言包是外部依赖**：本机缺数据，需用户确认是否允许安装（或改为可选，缺语言包时明确提示）。

---

## 5. 建议顺序

`A → B → C → D → E`：A 是地基，B 让手感接近 QQ/PixPin，C 是 PixPin 的招牌且相对独立，D/E 都是独立新功能、风险各自评估。

**Phase A 之前先做一件事**：为"就地编辑"写一个 Phase 0 式的**可行性探针**——
验证 layer-shell 覆盖层上能否稳定地做「1:1 绘制 + 自绘工具条 + 连续鼠标交互」而不引入输入/合成问题。
这是整条路的地基，用探针先验掉，比直接在主链路上改安全得多。
